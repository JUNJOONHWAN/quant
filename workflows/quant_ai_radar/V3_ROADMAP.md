# Quant AI Radar V3: 학습된 AI 활용 극대화 계획

## 1. V3의 목표

V3는 Qwen3-8B Quant LoRA를 단순한 일회성 문장 생성기가 아니라, 매일
누적되는 시장 구조 판단 엔진으로 활용한다. 숫자 계산과 데이터 정합성은
계속 Python/Oracle이 맡고, 모델은 다음 고부가가치 판단에 집중한다.

- 무엇이 어제와 달라졌는지
- 가격, ETF Flow, 구성종목 전달 중 무엇이 서로 확인·충돌하는지
- 지금 강한 테마가 확산 중인지 소수 종목에 집중됐는지
- 강세·약세 후보의 가장 강한 반대 증거가 무엇인지
- 과거 유사 국면과 지금의 결정적 차이가 무엇인지
- 다음 세션에서 어떤 조건을 확인해야 기존 판단을 유지·폐기할지

V3도 주문을 만들지 않는다. 후보, 위험, 확인 조건, 판단 변화와 신뢰도
보정까지 제공하고 최종 투자 판단은 사용자에게 남긴다.

## 2. 유지할 불변 계약

1. Oracle만 FMP/Massive 공통 DB를 갱신하는 single writer다.
2. ETF Flow는 provider availability D+1/D+2 계약 이후에만 보인다.
3. ETF 구성종목도 acceptance 다음 미국 세션 이후에만 보인다.
4. 현재 상장 목록으로 과거 상폐·변경 종목을 제거하지 않는다.
5. Python이 사실·수치·순위·해시를 계산하고 모델은 이를 변경하지 않는다.
6. 승인된 `qwen3-8b-quant-lora-v1`만 판단을 작성하며 fallback 문구나
   다른 모델로 정상 결과를 꾸미지 않는다.
7. 일일 추론과 재학습을 분리한다. 매일 데이터를 넣어 판단하되, 새
   adapter는 별도 동결 테스트와 GREEN release gate 후에만 교체한다.
8. 실주문과 연결하지 않는다.

## 3. V3 일일 추론 구조

```text
Oracle 증분 갱신과 snapshot seal
  -> 전체 종목/ETF 정량 스캔
  -> 변화·이상·회전·괴리·전달효과 후보 추출
  -> 관련 과거 국면 검색
  -> LoRA 1차 종목/ETF 판단
  -> LoRA 2차 반대증거·폐기조건 검토
  -> LoRA 시장/섹터 교차합성
  -> 어제 판단과 비교한 change report
  -> 품질·신선도·캘리브레이션 게이트
  -> 시장/회전/후보/위험/개별종목 리포트
  -> 420px 이메일 + CLI/API
```

모델 호출량은 고정 티커 수가 아니라 정보가치로 배분한다. 전체 수치는
항상 전수 계산하고, 생성 추론은 다음 우선순위로 쓴다.

1. 새로 생긴 강한 ETF Flow와 가격 확인
2. 가격과 Flow의 방향이 바뀐 종목
3. 섹터 회전의 선두·후발·이탈 후보
4. 여러 ETF에서 동일 방향으로 전달되는 구성종목
5. 기존 판단의 신뢰도가 크게 변한 종목
6. 사용자가 명시적으로 요청한 종목

## 4. 새 AI 산출물

### 시장 구조 리포트

- 현재 국면과 전일 대비 변화
- breadth, concentration, correlation/topology, rotation
- 위험선호가 확산인지 대형주 집중인지
- 가장 강한 확인 증거와 반대 증거
- 판단을 뒤집을 다음 확인 조건

### 섹터·테마 회전 리포트

- 유입 초기, 확산, 과열, 둔화, 이탈의 5단계
- 선두 ETF와 영향 종목
- Flow 선행/가격 선행/동시 확인 구분
- 회전 지속 가능성과 반대 시나리오

### 후보·위험 리포트

- 강세 확인 관찰 후보
- 약세 확인 위험 후보
- 가격–Flow 괴리 후보
- 신규 이상치와 전일 판단 변화
- 후보별 근거, 반대 증거, 무효화 조건, 데이터 신선도

### 개별 종목 리포트

- ETF 관계가 없어도 요청 시 분석
- 관련 ETF와 보유비중/Flow 전달 경로
- 가격 구조, 시장·섹터 상대강도, 과거 유사 국면
- 어제 판단과 오늘 판단의 차이
- 알려진 사실, 모델 해석, 미확인 사항을 분리

### 역사·사후검증 리포트

- 당시 판단은 당시 가용 데이터만 보관
- 1/5/20 세션 뒤 결과를 별도 라벨 저장
- regime/confidence별 적중률과 calibration
- 후보 편향, 섹터 편향, 장세별 약점
- 모델 교체 전후 동일 기간 재생 비교

## 5. 장기 기억과 과거 유사 국면

V3는 자유서술을 다시 prompt에 무한 누적하지 않는다. 매일 다음 구조화
레코드만 보존한다.

- Oracle source fingerprint와 기준일
- 정량 feature snapshot
- 사용한 evidence ID
- 모델 regime/confidence/conclusion
- counter-evidence/unknown/confirmation condition
- 전일 대비 판단 변화
- 미래에 별도로 붙인 1/5/20 세션 평가 라벨

유사 국면 검색은 미래 라벨을 현재 prompt에 넣지 않고, 당시까지 보였던
feature와 판단만 검색한다. 사후 성과는 별도 평가 화면에서만 사용한다.

## 6. 추가 학습 계획

V3 후보 adapter는 현재 모델을 폐기하지 않고 병렬로 만든다.

1. 현재 60,000행 SFT 레시피를 재현 가능한 기준선으로 고정
2. 일일 운영에서 발견된 실제 실패를 유형별로 수집
3. `판단 변화`, `반대증거 검토`, `시장 교차합성`, `과거 국면 차이`
   과제를 새 학습 row로 설계
4. 중복 제거, PIT 재생성, 시간 분할과 embargo 적용
5. 기존 21,106개 frozen test와 신규 V3 challenger test를 모두 평가
6. 숫자 충실도, lookahead 0, 거래지시 0, schema, calibration, 안정성을
   모두 통과한 adapter만 새 release manifest로 승격

일시중지된 FMP 재무·기관·내부자·뉴스 백필은 수집 완료와 PIT 공개시점
계약이 검증된 뒤에만 V3 학습 후보가 된다. 단순히 DB에 있다는 이유로
현재 모델 prompt에 넣지 않는다.

## 7. 단계별 구현

### V3.1: 판단 변화와 일일 기억

- 전일/금일 diff packet
- 판단 변화 이유와 무효화 조건
- daily judgement ledger
- 420px 이메일에 “오늘 달라진 것” 추가

완료 게이트: 동일 입력 재현성, 미래 날짜 0, 전일 링크 누락 0.

### V3.2: 과거 유사 국면과 캘리브레이션

- feature-vector retrieval
- 유사점과 차이점의 모델 해석
- regime/confidence별 1/5/20 세션 scorecard
- 과신 구간 자동 경고

완료 게이트: point-in-time retrieval 감사, leakage test, walk-forward
재현성, calibration 개선.

### V3.3: 다단계 AI 심사

- 1차 판단
- 같은 LoRA의 반대증거/폐기조건 reviewer pass
- 시장·섹터 synthesis pass
- 불일치 시 신뢰도 하향 또는 사람 확인 대기

완료 게이트: 단일 pass 대비 반대증거 회수율과 안정성 개선, 처리시간이
일일 운영창 안에 유지.

### V3.4: V3 adapter challenger

- 운영 실패 사례 기반 새 과제
- 기존 adapter와 blinded A/B
- 전체 frozen test + 신규 V3 test
- GREEN release 이후에만 endpoint 교체

완료 게이트: 기존 모델보다 핵심 지표가 나빠지지 않고, 새 과제와
calibration이 개선되며 prohibited violation이 0.

## 8. 운영 우선순위

현재 기본 V2 자동화를 먼저 매일 안정적으로 누적한다. 그 기록이 V3의
실제 실패 데이터와 캘리브레이션 기준이 된다. 권장 순서는 다음과 같다.

1. V2 일일 자동화·메일을 2주 관찰
2. V3.1 판단 변화/기억 구현
3. V3.2 유사 국면/사후검증 구현
4. V3.3 다단계 reviewer를 shadow로 비교
5. 충분한 실패 사례가 쌓인 뒤 V3 adapter 학습

이 순서는 AI 사용을 줄이기 위한 것이 아니다. 현재 승인 LoRA를 매일
최대로 활용하면서, 모델이 실제로 못한 부분만 다음 학습 데이터로
전환해 V3가 측정 가능한 개선이 되도록 하기 위한 순서다.
